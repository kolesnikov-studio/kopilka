| D-15 | Валюты в UI (M3) | **Выбор из встроенного офлайн-списка ISO 4217, без свободного ввода** | Приложение поставляет константный список валют (код, символ, ISO-экспонент, название); пользователь добавляет валюту выбором, код и символ не редактируются. Свободный ввод кода отклонён: опечатка в PK ломает слияние файлов и будущий синк, список снимает проблему навсегда. Экспонент из списка задаёт масштаб ввода/вывода (валюты без копеек — без дробной части); в БД он не хранится — это свойство кода валюты. Сетевая подгрузка курсов в M3 отклонена: приватность §5; дверь оставлена — возврат к вопросу после 1.0 с явным opt-in в настройках (решение мейнтейнера 2026-09-26). Состав списка: полный ISO 4217 (~160 записей, решение мейнтейнера 2026-09-26) |
| D-16 | Курсы (M3) | **Ручной курс в rate_to_base, без истории; отчёты переоцениваются по текущему курсу** | Курс меняет только пользователь, вручную (Настройки → Валюты); у базовой валюты курс всегда 1 (поле скрыто в UI, DAO контролирует). Историю курсов не ведём. Истина — суммы в валюте счёта; пересчёт в базовую — линза просмотра: агрегаты отчётов считаются по текущему курсу и меняются вместе с ним. Курс на момент операции фиксируется только там, где деньги реально перешли из валюты в валюту, — в переводе (D-17). Альтернатива «хранить курс на каждой расходной операции» отклонена: данные v0.1–v0.2 курса не содержат (миграция наполнялась бы догадками), а исправление ошибочного курса не должно требовать правки истории операций |
| D-17 | Переводы между валютами (M3, схема v3) | **Одна операция, две суммы: списание + зачисление; курс — производная величина** | Перевод между счетами в разных валютах — одна строка transactions: amount_minor (списание, валюта счёта списания) и новая nullable-колонка target_amount_minor (зачисление, валюта счёта зачисления). NULL = перевод в одной валюте — все существующие данные остаются валидными без правки. Правила DAO: валюты счетов различаются ⇔ обе суммы обязательны и правятся только вместе; валюты совпадают ⇔ колонка обязана быть NULL. Курс отдельным полем не хранится — он производный (отношение сумм), один источник истины; комиссия обмена видна как расхождение сумм. Альтернативы отклонены: две связанные строки-«ноги» (ломают список операций и слияние) и отдельная таблица конвертаций (избыточна) |
| D-18 | Балансы и отчёты (M3) | **Пересчёт в базовую на лету, без кэша; смешанные валюты помечаются явно** | Балансы счётов остаются в валюте счёта (§3); общий баланс дашборда — сумма балансов, конвертированных текущим курсом. Агрегаты, которые сейчас складывают сырые amount_minor (донат категорий, динамика месяцев), обязаны конвертировать каждую операцию в базовую до суммирования: построчное округление до минорной единицы базы, результат — INTEGER (деньги по-прежнему int, курс — не деньги). Честность смешанных валют: список операций — в валюте операции, агрегаты — в базовой с символом и пометкой «по текущему курсу». Кэш пересчитанных сумм отклонён: инвалидация при каждом изменении курса противоречит принципу «балансы не хранятся»; объёмы персонального учёта малы, потоки drift пересчитывают всё сами |
| D-19 | Бюджеты (M3) | **Лимит всегда в базовой валюте, схема не меняется** | limit_minor трактуется как минорные единицы базовой валюты; прогресс = расходы категории за месяц, конвертированные по текущему курсу (D-18), против лимита. У категории валюты нет и не появится, а бюджет — про «сколько я себе разрешаю в валюте, в которой думаю», то есть в базовой; сменить её можно (D-20). Альтернатива «валюта у бюджета» отклонена: лишняя колонка схемы, лишний выбор в диалоге, неоднозначность расходов категории в разных валютах |
| D-20 | Базовая валюта (M3) | **Смена разрешена; курсы остальных валют пересчитываются автоматически** | Смена базовой в настройках переводит is_base и пересчитывает rate_to_base остальных живых валют из старых (новый курс = старый курс / старый курс новой базы), одной транзакцией, с подтверждением в UI; посев RUB остаётся значением по умолчанию для новых установок. Включено в этап M3 решением мейнтейнера 2026-09-26. Альтернатива «запретить смену после первого запуска» отклонена: seed-выбор RUB не обязан совпадать с валютой пользователя, а вручную «выворачивать» курсы никто не должен |
| D-21 | Схема v3 и бэкап v3 (M3) | **Одна nullable-колонка; миграция ALTER TABLE; бэкап v3 читает v1/v2** | schema_version 3 = v2 + transactions.target_amount_minor INTEGER NULL; миграция добавляет колонку без перезаписи данных, с обязательным тестом по образцу migration_v2_test (старые переводы остаются NULL и считаются одно-валютными). Формат бэкапа v3: в строках transactions появляется необязательное поле target_amount_minor; чтение v1/v2 не меняется (нет поля = NULL). Валидация импорта строгая: не-перевод с заполненной колонкой или перевод между разными валютами без неё — отказ, не тихий пропуск. Следствие: строка DoD M3 («схема БД не изменилась») заменена на «схема v3: одна nullable-колонка, миграция с тестом» |
| D-22 | Округление при конвертации (M3) | **Half-up по модулю, знак отдельно** | Конвертация в базовую (D-18) округляется построчно до минорной единицы базы: `round()` половину вверх по модулю, знак сохраняется отдельно. Альтернатива banker's rounding отклонена: конвертация — линза просмотра (D-16) и агрегаты отчётов, а не расчёты; важнее интуитивность «как на калькуляторе», чем статистическая нейтральность. Реализация — core (R2 ревью); зафиксировано до M3-шага 5 |
| D-23 | Названия валют (M3) | **Константный справочник в core, не .arb** | Названия валют (RU/EN) вместе с кодом/символом/экспонентом — константный словарь в `core/currency.dart` рядом с ISO-списком (D-15). Это осознанное отклонение от конвенции «l10n только через .arb»: справочные данные — не интерфейсные тексты; 160×2 ключей замусоривают .arb и замедляют gen-l10n. Граница: всё, что пользователь читает как интерфейс (кнопки, подсказки, ошибки, состояния) — .arb; словарные данные (названия, символы, экспоненты валют) — core. Код всегда показывается рядом с названием, fallback не нужен. Из UX-спеки B1.5, ревью 2026-09-26 |
| D-24 | Валюта счёта (M3) | **Неизменяема при живых операциях; смена — только для пустого счёта** | Операция хранит код валюты счёта на момент записи — смена валюты счёта с историей сделала бы её ложной. UI (M3-шаг 3): в режиме правки счёта с операциями валюта показывается строкой без правки; счёт без операций — сменить можно (DAO уже отказывает при `accountHasTransactions`, отказ остаётся последней линией). Перенос средств между валютами — не смена валюты, а серия переводов-конвертаций (D-17/B4). Альтернатива «смена с предупреждением» отклонена: пользователь не может оценить последствия для сотен операций. Из UX-спеки B2.2, ревью 2026-09-26 |
| D-25 | Валидация импорта бэкапа v3 (M3) | **Строгая: противоречие с правилами D-17 — отказ, не тихая нормализация** | Дополнение к D-21, ревью M3-шага 1 (2026-09-27): три случая — отказ импорта: не-перевод с заполненным `target_amount_minor`; перевод между разными валютами без него; перевод в одной валюте с заполненным (следствие «валюты совпадают ⇔ NULL»). Тихая нормализация скрыла бы противоречие данных с правилами и породила бы невалидные состояния при будущих правках; отказ до транзакции импорта не трогает базу. Проверка формы перевода (`target_account_id` без `type='transfer'` и наоборот) распространена и на старые файлы v1/v2 (A13). Подтверждено при ревью |
| D-26 | Справочник валют: состав и API (M3-шаг 2) | **ISO-список 157 записей; идемпотентный `changeBase`; курс с 6 значащими знаками** | Ревью M3-шага 2 (2026-09-27): (а) состав справочника — 157 «обычных» национальных валют и валют союзов; X-пробелы (XAU/XDR/XTS/XXX и др.), памятные и заменённые коды (MRO/STD/VEF/ZWL и др.) исключены — в списке только то, что пользователь может осмысленно выбрать для личного учёта; корректировка состава = правка одного data-файла, без отдельной задачи. (б) `changeBase` для уже базовой валюты — успешный выход без записи (повторный запрос текущей базовой — не ошибка пользователя; отказ `invalidInput` сделал бы повтор снеком «проверьте ввод» ложно). (в) Формат курса на экране — до 6 значащих знаков без хвостовых нулей; курс — не деньги (int-правило §3 на него не распространяется), точность парсинга и показа расширяется одной согласованной константой. (г) `setBase` остаётся низкоуровневой операцией DAO, все UI-пути смены базовой — только через `changeBase`. |
| D-27 | Валюта счёта и дробность (M3-шаг 3) | **Ввод/показ по экспоненту валюты; смена валюты очищает поле суммы** | Ревью M3-шага 3 (2026-09-27): (а) поля суммы и показ в списках параметризованы экспонентом валюты счёта (JPY — без дробной части, KWD — три знака); ранее суммы неявно считались в экспоненте 2, что записывало неверные минорные суммы для валют с другим экспонентом. (б) При смене валюты в форме счёта и смене счёта в форме операции поле суммы очищается: пересчёт по курсу невозможен (курса «валюта → валюта» в справочнике нет, история курсов не ведётся — D-16), а оставленное значение было бы ложным в новой валюте. (в) У целевых валют (экспонент 0) форматтер не принимает пробелы-группировку — норма v0.3, унификация в бэклоге M4. (г) Валидатор выбора валюты в форме счёта остаётся guard'ом, хотя дефолт «базовая валюта» делает его в UI-потоке недостижимым (B2.1). |
