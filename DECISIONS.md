# Реестр решений (ADR-подобный формат)

Ключевые решения проекта. Изменение любого пункта — только через запись нового решения с датой и обоснованием (старое не удаляем).

| # | Решение | Выбор | Обоснование (кратко) |
|---|---------|-------|----------------------|
| D-01 | Фреймворк | **Flutter (Dart)** | Одна кодовая база и UI на все 4 платформы, свой рендеринг (не WebView), зрелые графики (fl_chart) и локальные БД (drift/SQLite) |
| D-02 | Целевые платформы v1.0 | **Windows, Linux, Android** | iOS отложена: нужен аккаунт Apple Developer $99/год и App Store/TestFlight. Код пишем iOS-совместимым, чтобы добавить без переделки |
| D-03 | Хранение данных | **SQLite локально на устройстве** (drift) | Без сервера, единая схема на всех платформах, надёжность, лёгкий экспорт/бэкап |
| D-04 | Синхронизация | **Нет. Экспорт/импорт файлов + автобэкапы** | Схема БД сразу проектируется совместимой с будущим синком (UUID, updatedAt, soft delete) |
| D-05 | Лицензия | **Проприетарная (all rights reserved)** | Код в репозитории открыт для ознакомления, но копирование/модификация/распространение запрещены; собранные копии из официальных Releases бесплатны для личного использования |
| D-06 | Дистрибуция | **GitHub Releases бесплатно** | Ноль затрат, полный контроль; открытие кода для финансового приложения необязательно при локальном хранении данных |
| D-07 | Каналы Android | **GitHub Releases (APK) с первого дня; Google Play и F-Droid — позже** | Полный контроль и ноль затрат на старте; сторы добавим, когда продукт дорастёт |
| D-08 | Каналы Desktop | **GitHub Releases: NSIS-установщик + portable для Windows, AppImage + .deb для Linux** | Бесплатно, работает с нашим механизмом обновлений |
| D-09 | Обновления MVP | **Уведомление + ссылка на релиз, единый механизм на всех платформах** | Приложение проверяет GitHub Releases (или JSON-манифест) по согласию пользователя (настройка вкл/выкл). Автоапдейтер Windows (auto_updater/Squirrel) — отдельная задача после релиза |
| D-10 | iOS | **Отложена** | Только уведомление об обновлениях возможно на iOS; вернёмся с рабочим продуктом |
| D-11 | Скоуп | **M1: ядро + экспорт/бэкапы; M2: отчёты + бюджеты; M3: мультивалютность в UI** | См. ROADMAP.md; модель мультивалютности закладывается в схему БД сразу, в M1 |
| D-12 | Название | **Рабочее имя «Kopilka»** (кодовое, заменить когда пользователь решит) | Нужно для имён пакетов/репозитория сейчас; замена названия позже — дешёвая операция |
| D-13 | Языки интерфейса | **RU + EN с первого дня** | Прямая генерация через .arb-файлы (flutter_localizations) |

## Открытые вопросы (не блокируют старт)

- Окончательное название приложения и домен/репозиторий (сейчас — Kopilka).
- Детальная категоризация: предустановленный набор категорий и иконки.
- Бюджеты: точная семантика (на месяц, скользящие, по категории/счёту) — решать на этапе M2.
- Стоит ли добавить CI-сборку Windows-артефактов с кодовой подписью (сертификат платный — по умолчанию нет).
- Будущая синхронизация: файловая (обмен .json между устройствами) vs облачная пользователя (WebDAV) — рассмотреть после M3.
